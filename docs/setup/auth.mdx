# E.2 Add authentication

<AddOnSwitch addon="auth" />
<StepApplies step="auth" />

This add-on makes the Api accept JWT access tokens from the identity provider of step E.1 ([Reference 8.16](../reference/spec/08-design-rules/16-authentication-and-authorization.mdx)).

- **Sign in is required everywhere by default.** `/health`, OpenAPI and the Scalar UI are explicitly public; any other public endpoint must say `.AllowAnonymous()`.
- **Permissions** come from a token claim. An endpoint asks for one with `.RequirePermission("orders.create")`.
- **`ICurrentUser`** gives Application the signed-in user's ID.

**2. Fill in the new package version and reference the package:**

<SnippetPackageVersions />

<FlagScope addon="auth">
<PackageCommands addon="auth" />
</FlagScope>

```bash
dotnet build
dotnet test
```

**3. Set the Development Authority and Audience** from step E.1 (not secret: `appsettings.Development.json` works too):

```bash
dotnet user-secrets set "Authentication:Authority" "https://<identity provider>" --project src/ProductName.Api
dotnet user-secrets set "Authentication:Audience" "<audience>" --project src/ProductName.Api
```

**4. Check it.** Start the Api, then:

```bash
API=$(awk -F'"' '/"http": *\{/{p=1} p&&/"applicationUrl"/{print $4; exit}' src/ProductName.Api/Properties/launchSettings.json)
curl -i $API/health         # 200, no token needed
curl -i $API/openapi/v1.json
curl -i $API/anything       # 401: every endpoint requires sign in by default
```

Then prove that a real token is accepted, not just that a missing one is rejected. Get an access token for the Api's audience the way step E.1 showed, then:

```bash
TOKEN=<access token>
curl -i -H "Authorization: Bearer $TOKEN" $API/anything   # 404: authenticated, and the path does not exist
```

A 401 here means `Authentication:Authority` or `Authentication:Audience` does not match the token; fix it before going further.
