# B.2 Add Messaging

<AddOnSwitch addon="messaging" />
<StepApplies step="messaging" />

This add-on lets the system tell the outside world, or its own Worker, that something happened, through RabbitMQ with MassTransit ([Reference 7.5](../reference/spec/07-optional-components.mdx#7-5-messaging), [8.4](../reference/spec/08-design-rules/04-masstransit-async-messaging.mdx)). It needs PostgreSQL.

- Application publishes **integration events** through `IEventBus` and never references MassTransit.
- MassTransit's **Outbox** writes each event to a table in the same transaction as the business data, then delivers it to RabbitMQ. An event is never lost, and never sent for data that was rolled back.
- Every Consumer gets an **Inbox**, so a message delivered twice is processed once.
- Without the Worker add-on the Api delivers the Outbox itself.

**3. Create the migration** for the Outbox and Inbox tables:

<SnippetAddMigration />

Use `AddMessaging` as the migration name. Open it: it must contain only the MassTransit `InboxState`, `OutboxMessage` and `OutboxState` tables.

**4. Run it.** Start RabbitMQ with the other local services, then the Api:

```bash
docker compose up -d
echo $MT_LICENSE_PATH        # the license from step B.1
dotnet run --project src/ProductName.Api
```

The RabbitMQ management UI is at [http://localhost:15672](http://localhost:15672) (guest / guest). The Api log in Seq shows the bus starting with no errors.

**5. Test** with Docker running and `MT_LICENSE_PATH` set:

```bash
dotnet test
```
