# 2.2 Application

Application holds the use cases, split by CQRS into **Commands** (change state) and **Queries** (read state). Each one is a MediatR request with exactly one handler, and every handler returns a `Result`.

- Our own `ICommand`, `IQuery` and handler interfaces wrap MediatR, so every use case has the same shape.
- Two **pipeline behaviors** run around every handler: logging, then validation with FluentValidation. Validation runs for Commands only.
- `DependencyInjection.cs` registers MediatR, the behaviors and every validator in one call.

No sample Command or Query is created now; features add their own ([Reference 8.15](../reference/spec/08-design-rules/15-feature-slices-vertical-slice.mdx)). The code is in [Reference 14](../reference/code/14-application.mdx).
