# F.1 Add the deployment files and CI

<AddOnSwitch addon="golive" />
<StepApplies step="ci" />

Go live takes the project to a SIT and a Production environment, each an Ubuntu VM behind Nginx with its own backing services ([Reference 7.7](../reference/spec/07-optional-components.mdx#7-7-go-live), [8.21](../reference/spec/08-design-rules/21-deployment.mdx)). Do it last: the files and steps include only what the project's other add-ons need.

This step adds the deployment templates under `deploy/` and the CI workflow. CI builds and runs every test on each push, and publishes the deployment artifact only when the tests pass.

<WhenOff addon="auth">

:::caution[No authentication]
This project has no Authentication add-on, so every endpoint will be public on SIT and Production. Add [Authentication](./identity-provider.mdx) first unless the Api is meant to be public.
:::

</WhenOff>

<Tabs groupId="route" queryString>
<TabItem value="manual" label="Manual" default>

**1. Create the files:**

<AddOnFiles addon="golive" />

**2. Set the CI secrets** before pushing, so the first run can pass:

<FlagScope addon="golive">

```bash
gh secret set MT_LICENSE < ~/.config/masstransit/license.txt   # @@messaging
# @@sonar-begin
gh secret set SONAR_TOKEN
gh variable set SONAR_PROJECT_KEY --body "<project key>"
gh variable set SONAR_ORGANIZATION_KEY --body "<organization key>"
# @@sonar-end
gh secret set QODANA_TOKEN   # @@qodana
```

</FlagScope>

Create the SonarCloud and Qodana projects first if you chose them in step 0.2.

**3. Commit, push and watch the run:**

```bash
git add -A && git commit -m "ci: add deployment files and CI workflow" && git push
gh run watch                        # follow the latest run
gh run view <run-id>                # the artifact productname-<sha> is listed at the bottom
```

If a run failed because a secret was missing, set it and re-run: `gh run rerun <run-id>`.
