# D.1 Add auditing

<AddOnSwitch addon="auditing" />
<StepApplies step="auditing" />

Auditing records what changed and who did what, from day one ([Reference 7.3](../reference/spec/07-optional-components.mdx#7-3-audit-records)). History that was never recorded cannot be recovered later. It needs PostgreSQL.

- **Data change audit**: an EF Core interceptor writes an `AuditTrails` row for every change to an entity marked `IAuditable`, with old and new values.
- **Operation audit**: a pipeline behavior writes an `OperationAudits` row for every run of a Command or Query marked `IAuditableRequest`, including failures.

The application account cannot change or delete audit rows on SIT and Production (Go live).

**4. Write down the audit rule** before features arrive: which kinds of entities implement `IAuditable`, which properties carry `[AuditIgnore]`, and which kinds of Commands or Queries implement `IAuditableRequest`. Put it in the agent instruction file so every feature slice follows it.
