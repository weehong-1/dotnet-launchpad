# 4.1 Ready for feature work

The Setup Flow ends here: the core Skeleton Solution runs, and no business feature exists yet.

## First, the add-ons

Most backends need some of the [Add-ons](./addons.mdx) before the first feature: a database to store aggregates, messaging to hand work to the background, sign in. Add them now, while no feature depends on the core's shape. Go live usually comes last.

## Then, features

From now on every use case is a feature slice ([Reference 8.15](../reference/spec/08-design-rules/15-feature-slices-vertical-slice.mdx)): a Command or Query with its handler and validator, an endpoint, and tests, all in one folder per use case. Building features is ordinary project work, not part of the setup.

When you write the first use case, fill in the angle brackets and give this prompt to the agent, once per use case:

<PromptFeatureSlice />

Keep it where you will find it: add it below the common rules in the agent instruction file (step 1.1), or bookmark this page.

To see how the pieces connect end to end, read the [Appendix A demo](../reference/appendix/a-demo-code.mdx). It assumes the PostgreSQL, Messaging and Authentication add-ons, and is a reading aid only: never copy it into the project.
