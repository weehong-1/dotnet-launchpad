# A.1 Add PostgreSQL

<AddOnSwitch addon="postgres" />
<StepApplies step="postgres" />

This add-on gives the project a database: EF Core with PostgreSQL ([Reference 7.4](../reference/spec/07-optional-components.mdx#7-4-postgresql)).

- `ApplicationDbContext` is both the unit of work (`IUnitOfWork`) and the read side for Queries (`IApplicationDbContext`). Before it saves, it publishes the aggregates' domain events through MediatR, so their handlers' changes commit in the same transaction.
- `Repository<TAggregate, TId>` is the base class for each aggregate's repository: write use cases load and save whole aggregates through it.
- Strongly typed IDs get a value conversion automatically, and `IHasTimestamps` entities get their times filled in.
- Every aggregate root gets optimistic concurrency on PostgreSQL's `xmin` column, and a conflict becomes a 409 response.

Docker runs PostgreSQL locally, and the integration tests start their own with Testcontainers.


**3. Install the EF Core tool and create the first migration.** It is empty: there are no tables until features add them.

```bash
dotnet new tool-manifest
dotnet tool install dotnet-ef
```

<SnippetAddMigration />

Use `InitialCreate` as the migration name.

**4. Run it.** Start PostgreSQL, then the Api, which applies migrations at startup in Development:

```bash
docker compose up -d
dotnet run --project src/ProductName.Api
```

Prove the Api refuses to start without real settings outside Development:

```bash
ASPNETCORE_ENVIRONMENT=SIT dotnet run --project src/ProductName.Api --no-launch-profile
# Expected: it fails at startup instead of connecting to the local database
```

**5. Test** with Docker running:

```bash
dotnet test
```
