## 11.1 Generating with an AI coding agent \{#11-1-generating-with-an-ai-coding-agent\}

Every section ends with a prompt that can be given to an AI coding agent (such as Claude Code, Cursor or GitHub Copilot) to generate that section's files.

**Steps**

1. Download `TEMPLATE.md` (the whole Reference as one file, see [Setup Flow step 1.1](../../setup/repository.mdx)) into the new project's repository at `docs/TEMPLATE.md` so the AI can read it.
2. Fill in the project settings of the **common rules** below and put them in the AI's project instruction file (such as `CLAUDE.md`, `AGENTS.md`, or `.github/copilot-instructions.md`, which GitHub Copilot reads automatically); if the tool has no instruction file, paste them at the start of each conversation.
3. Go through sections [12](./12-solution-level.mdx) to [18](./18-tests.mdx) in order, pasting one section's prompt at a time, and move on only when its done conditions pass.
4. To do it all at once, use the **generate everything** prompt below instead. The first time you use the template, going section by section makes problems easier to spot.

Besides the common rules, the project instruction file should also state: build and run commands (see [8.10](../spec/08-design-rules/10-local-development.mdx), [8.11](../spec/08-design-rules/11-database-migrations.mdx)), layering rules (see section [3](../spec/03-layers-and-dependency-direction.mdx)), key conventions (CQRS, Result, feature slices), testing conventions, and the tech stack with versions.

## 11.2 Scaffolding the solution with the CLI \{#11-2-scaffolding-the-solution-with-the-cli\}

Without an AI, these commands build the section [5](../spec/05-solution-structure.mdx) structure and the [12.2](./12-solution-level.mdx#12-2-directory-packages-props) project references by hand, equivalent to steps 1, 2 and 6 of the [12.11](./12-solution-level.mdx#12-11-ai-coding-agent-prompt) prompt. ## 11.3 GlobalUsings.cs per project \{#11-3-globalusings-cs-per-project\}

The Boilerplate files leave out `using` directives for the solution's own namespaces. Each project gets one `GlobalUsings.cs` at its root instead, so every file compiles exactly as shown. Create it **after** the project's other files: a global using of a namespace that does not exist yet fails the build. Lines marked for an add-on are left out when the project does not include it, and added together with that add-on's files.

## 11.4 Core and add-on files \{#11-4-core-and-add-on-files\}

The core Skeleton Solution is every file above without an "add-on" mark. Each add-on brings its own files and changes a few core files; its Setup Flow page shows both, with the changed lines highlighted.

| Add-on | Requires | New files | Core files it changes |
| --- | --- | --- | --- |
| PostgreSQL | None | Application `Abstractions/Data/*`; Infrastructure `Database/*`; Api `Extensions/MigrationExtensions.cs`; the first migration | `Directory.Packages.props`, `docker-compose.yml`, Infrastructure `DependencyInjection.cs`, Api `GlobalExceptionHandler.cs`, `Program.cs` and appsettings, the integration test base, `GlobalUsings.cs` |
| Messaging | PostgreSQL | Application `IEventBus.cs`; Infrastructure `Messaging/EventBus.cs`; the Outbox and Inbox migration | `Directory.Packages.props`, `docker-compose.yml`, `ApplicationDbContext.cs`, Infrastructure `DependencyInjection.cs`, appsettings, the integration test factory, `GlobalUsings.cs` |
| Worker | Messaging | The Worker project (section [17](./17-worker-optional.mdx)) | Infrastructure `DependencyInjection.cs`, `LayerTests.cs`, the solution |
| Auditing | PostgreSQL | Domain, Application and Infrastructure `Auditing` files; the audit tables migration | Application and Infrastructure `DependencyInjection.cs`, `GlobalUsings.cs` |
| Authentication | None | Application `Abstractions/Authentication/*`; Infrastructure `Authentication/*`; Api `Extensions/AuthExtensions.cs` and `Authorization/*` | `Directory.Packages.props`, Infrastructure `DependencyInjection.cs`, `Program.cs` and appsettings, `GlobalUsings.cs` |
| Go live | None | `deploy/*`, `.github/workflows/ci.yml`, `qodana.yaml` (Qodana only) | None |
