# 6. Layer responsibilities \{#6-layer-responsibilities\}

Items marked with an add-on exist only once the project includes it (see [7](./07-optional-components.mdx)).

## 6.1 Domain \{#6-1-domain\}

- Aggregate roots, entities, value objects
- Domain events
- Domain exception (`DomainException`)
- Repository interfaces (implemented with the PostgreSQL add-on)
- Common base types and interfaces: `Entity`, `AggregateRoot`, `IDomainEvent`, `IStronglyTypedId`, `IHasTimestamps`; auditing adds `IAuditable` and `[AuditIgnore]`
- Value objects use `record` directly, with no base class

## 6.2 Application \{#6-2-application\}

- Organised as feature slices: `Features/{Feature}/{UseCase}/`, with each use case's Command or Query, Validator, Handler and Response in one folder (see [8.15](./08-design-rules/15-feature-slices-vertical-slice.mdx))
- Integration events (outbound message contracts, Messaging add-on) live in `IntegrationEvents/` and belong to no slice
- Input validation
- Pipeline behaviors: logging, operation audit (Auditing add-on), validation
- DTOs
- Abstractions implemented by Infrastructure, such as current user, message publishing, external service clients

**No transaction pipeline** (PostgreSQL add-on): each Command calls `SaveChangesAsync` once, and EF Core puts every change of that save (including Outbox messages produced by domain events) in one transaction. Only when a Command must save several times and all saves must succeed or roll back together does that handler open its own transaction.

## 6.3 Infrastructure \{#6-3-infrastructure\}

- EF Core DbContext, entity configuration, migrations (PostgreSQL add-on)
- Repository implementations (PostgreSQL add-on)
- Authentication related implementations: current user, permission source (Authentication add-on)
- Writing audit records (Auditing add-on)
- Message publishing with MassTransit (Messaging add-on)
- External service clients (third party APIs, email, file storage and so on, as the project needs), all with the resilience handler
- Health check registration

## 6.4 Api \{#6-4-api\}

- HTTP endpoints, with folders matching Application's feature slices
- Middleware
- Authentication and permission based authorization (Authentication add-on)
- Rate limiting
- Unified error handling (ProblemDetails)
- OpenAPI documentation
- Health check endpoint
- CORS
- Automatic migrations in development (PostgreSQL add-on)
