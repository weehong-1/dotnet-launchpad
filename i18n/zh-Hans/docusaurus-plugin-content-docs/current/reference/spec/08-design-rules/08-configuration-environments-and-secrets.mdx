# 8.8 设定、环境与机密 \{#8-8-configuration-environments-and-secrets\}

**三个环境**

| 环境 | 用途 | 环境名称 |
| --- | --- | --- |
| Development | 开发者本机 | `Development` |
| SIT | 系统整合测试，部署后供测试人员验证 | `SIT` |
| Production | 正式环境 | `Production` |

- Api 以 `ASPNETCORE_ENVIRONMENT`、Worker 以 `DOTNET_ENVIRONMENT` 指定环境名称。
- 未设定时 .NET 默认为 `Production`，因此漏设环境变量时会套用最严格的设定，不会意外开放开发功能。
- 本机开发由 `launchSettings.json` 设为 `Development`，不需手动设定。
- 环境名称必须与设定档名称**大小写完全一致**。Linux 的文件系统区分大小写，环境名称写成 `Sit` 会找不到 `appsettings.SIT.json`。

**设定档分层**

每个 Api 与 Worker 各有四个设定档，.NET 先载入基础档，再以环境档覆盖：

1. `appsettings.json`：基础档，放所有环境共用的结构与**最安全的预设值**（功能全部关闭、连接字符串留空）。
2. `appsettings.Development.json`：本地 Docker 的连接字符串、开启 OpenAPI 与启动时迁移、较详细的日志。
3. `appsettings.SIT.json`：开启 OpenAPI 供测试人员使用，其余与正式环境相同。
4. `appsettings.Production.json`：只放正式环境与基础档不同的部分。

各档内容见 [16.12](../../code/16-api.mdx#16-12-appsettings-files-4) 与 [17.1](../../code/17-worker-optional.mdx#17-1-appsettings-files-4)。

**各环境的差异**

| 设定 | Development | SIT | Production |
| --- | --- | --- | --- |
| 连接字符串 | 设定档（本地 Docker 预设值） | 环境变量或机密管理服务 | 环境变量或机密管理服务 |
| MediatR 授权金钥 | User Secrets | 环境变量或机密管理服务 | 环境变量或机密管理服务 |
| 身份认证 Authority 与 Audience | 设定档或 User Secrets | 环境变量 | 环境变量 |
| OpenAPI 与 Scalar | 开启 | 开启 | 关闭 |
| 启动时自动迁移 | 开启 | 关闭（与正式环境相同流程） | 关闭 |
| Seq 网址与 API key | 设定档（本地 Docker） | 环境变量 | 环境变量 |
| 日志输出 | 控制台 + 本地 Seq | 控制台（Warning 以上）+ 本机 JSON 文件 + Seq | 同 SIT |
| 日志文件保留 | 不写文件 | 14 天 | 30 天 |
| 日志等级 | Debug | Information | Information |
| CORS | 本地前端网址 | SIT 前端网址 | 正式前端网址 |

**原则**

- SIT 除了 OpenAPI 之外，**尽量与正式环境一致**，包括迁移方式与日志格式，让部署流程在 SIT 先演练过一次。
- 开关类功能（OpenAPI、启动时迁移）以设定控制，不在代码中判断环境名称，新增环境时只需加一个设定档。
- 设定档中的**数组在多个档案之间按索引合并**，不是整个取代。因此 Serilog 的 `WriteTo` 使用**具名物件**（`Console`、`File`、`Seq`）而不是数组，并且只在环境档中定义；也不写 `Using` 区块，由 Serilog 自动载入已引用的套件。具名物件的另一个好处是可以用环境变量覆盖个别设定，例如 `Serilog__WriteTo__Seq__Args__serverUrl`。

**机密**

- 设定档只放**非机密**的值。SIT 与正式环境的密码、授权金钥等机密资料**不得提交到版本控制**；本地 Docker 的预设帐号密码不属于机密，可以写在 `appsettings.Development.json`，让本地开发开箱即用。
- 本地开发使用 .NET User Secrets（`dotnet user-secrets set "键" "值"`）存放机密。
- SIT 与正式环境使用环境变量或云端机密管理服务（如 Azure Key Vault、AWS Secrets Manager）。环境变量以双底线表示层级，例如 `ConnectionStrings__Database`。
- SIT 与正式环境必须使用**不同的**数据库、消息中间件与机密，不可共用。
- MassTransit v9 授权从环境变量读取：`MT_LICENSE` 放授权内容，或以 `MT_LICENSE_PATH` 指向授权文件。本机把文件放在 repo 之外，并在 shell 设定档中 export `MT_LICENSE_PATH`；VM 上在环境变量文件中设定 `MT_LICENSE`（12.9）；CI 使用 `MT_LICENSE` secret（12.10）。它绝不提交到版本控制。没有它，Api、Worker 与整合测试都会在启动时失败。
