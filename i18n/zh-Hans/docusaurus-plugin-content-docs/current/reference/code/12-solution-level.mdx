# 12. 解决方案层级 \{#12-solution-level\}

## 12.1 Directory.Build.props \{#12-1-directory-build-props\}

```xml
<Project>
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>
    <AnalysisLevel>latest</AnalysisLevel>
  </PropertyGroup>
  <ItemGroup>
    <AdditionalFiles Include="$(MSBuildThisFileDirectory)BannedSymbols.txt" />
  </ItemGroup>
</Project>
```

`EnforceCodeStyleInBuild` 让 `.editorconfig` 的代码风格规则在建置时也会检查，配合 `TreatWarningsAsErrors`，风格不符会直接建置失败。

| 项目 | 项目引用 | NuGet 包 |
| --- | --- | --- |

| Application | Domain | `MediatR`、`FluentValidation`、`FluentValidation.DependencyInjectionExtensions`、`Microsoft.EntityFrameworkCore`、`Microsoft.Extensions.Configuration.Abstractions` |

| Application.UnitTests | Application | `xunit` 系列、`NSubstitute`、`Microsoft.Extensions.TimeProvider.Testing` |

## 12.3 global.json \{#12-3-global-json\}

```json
{
  "sdk": {
    "version": "10.0.100",
    "rollForward": "latestFeature"
  },
  "test": {
    "runner": "Microsoft.Testing.Platform"
  }
}
```

版本号按建立模板时安装的 SDK 调整（英文 guide 使用 10.0.103）。`latestFeature` 会前滚到已安装、主版本与次版本相同（10.0）的最新 SDK，包括较新的功能带，例如 10.0.2xx。`test` 区段让 `dotnet test` 使用 xUnit v3 所需的 Microsoft.Testing.Platform，其选项与 VSTest 不同（见 [8.10](../spec/08-design-rules/10-local-development.mdx)、[8.12](../spec/08-design-rules/12-testing-strategy.mdx)）。

## 12.5 docker-compose.yml \{#12-5-docker-compose-yml\}

```yaml
services:
  postgres:
    image: postgres:17
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: productname
    ports:
      - "127.0.0.1:5432:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data

  rabbitmq:
    image: rabbitmq:4-management
    ports:
      - "127.0.0.1:5672:5672"
      - "127.0.0.1:15672:15672"

  seq:
    image: datalust/seq:latest
    environment:
      ACCEPT_EULA: "Y"
      SEQ_FIRSTRUN_NOAUTHENTICATION: "true"
    ports:
      - "127.0.0.1:5341:80"

volumes:
  postgres-data:
```

**只供本地开发使用**，帐号密码均为预设值，因此所有端口只发布在 `127.0.0.1`，网络上的其他机器无法连线。启动后：RabbitMQ 管理界面在 `http://localhost:15672`（帐号密码 guest），Seq 在 `http://localhost:5341`。

## 12.6 BannedSymbols.txt \{#12-6-bannedsymbols-txt\}

```text
P:System.DateTime.Now;使用 TimeProvider.GetUtcNow()，数据库一律存 UTC（见 8.20）
P:System.DateTime.Today;使用 TimeProvider.GetUtcNow() 并明确指定时区（见 8.20）
P:System.DateTimeOffset.Now;使用 TimeProvider.GetUtcNow()（见 8.20）
```

由 `Microsoft.CodeAnalysis.BannedApiAnalyzers` 读取，使用清单中的 API 会产生警告，配合“警告视为错误”直接导致建置失败。日后发现其他应禁用的 API，加入此清单即可。

## 12.7 deploy/systemd 服务文件 \{#12-7-deploy-systemd-service-files\}

`deploy/systemd/productname-api.service`：

```ini
[Unit]
Description=ProductName Api
After=network-online.target
Wants=network-online.target

[Service]
Type=notify
User=productname
Group=productname
WorkingDirectory=/opt/productname/api
ExecStart=/opt/productname/api/ProductName.Api
EnvironmentFile=/etc/productname/api.env
Environment=ASPNETCORE_URLS=http://127.0.0.1:5000
Restart=always
RestartSec=5
TimeoutStopSec=30
SyslogIdentifier=productname-api
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ReadWritePaths=/var/log/productname

[Install]
WantedBy=multi-user.target
```

<Optional when="worker">

`deploy/systemd/productname-worker.service`（可选：Worker）：

```ini
[Unit]
Description=ProductName Worker
After=network-online.target
Wants=network-online.target

[Service]
Type=notify
User=productname
Group=productname
WorkingDirectory=/opt/productname/worker
ExecStart=/opt/productname/worker/ProductName.Worker
EnvironmentFile=/etc/productname/worker.env
Restart=always
RestartSec=5
TimeoutStopSec=30
SyslogIdentifier=productname-worker
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ReadWritePaths=/var/log/productname

[Install]
WantedBy=multi-user.target
```

</Optional>

- `Type=notify` 搭配程序中的 `AddSystemd()`（见 [16.13](./16-api.mdx#16-13-program-cs)、[17.2](./17-worker-optional.mdx#17-2-program-cs)）：应用启动完成才回报 systemd，停止时能正确完成进行中的工作。
- Api 只监听本机的 5000 埠，外部请求一律经过 Nginx。
- 环境名称与机密都放在 `EnvironmentFile` 中，服务文件在各环境完全相同。
- `Restart=always` 让服务异常结束时自动重启；`ProtectSystem` 等设定限制服务能写入的位置。

## 12.8 deploy/nginx/productname-api.conf \{#12-8-deploy-nginx-productname-api-conf\}

```nginx
server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "no-referrer" always;

    client_max_body_size 10m;

    location / {
        proxy_pass         http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header   Host $host;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

- `api.example.com` 替换为实际网域；凭证由 certbot 申请与自动续期。
- HTTP 一律转向 HTTPS；安全标头在 Nginx 统一加上，应用不需处理。
- `X-Forwarded-For` 与 `X-Forwarded-Proto` 让 Api 取得真实的客户端 IP 与通讯协定（见 [16.13](./16-api.mdx#16-13-program-cs) 的转发标头设定）。
- `client_max_body_size` 为上传大小上限，按项目需要调整。

## 12.10 .github/workflows/ci.yml \{#12-10-github-workflows-ci-yml\}

```yaml
name: ci

on:
  push:
    branches: [ main ]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    env:
      MT_LICENSE: ${{ secrets.MT_LICENSE }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-dotnet@v4
        with:
          global-json-file: global.json

      - run: dotnet restore
      - run: dotnet build --no-restore -c Release
      - run: dotnet test --no-build -c Release

      - run: dotnet publish src/ProductName.Api -c Release -r linux-x64 --self-contained -o artifacts/api
      - run: dotnet publish src/ProductName.Worker -c Release -r linux-x64 --self-contained -o artifacts/worker  # @@worker

      - run: dotnet tool restore
      - run: >
          dotnet ef migrations bundle
          --project src/ProductName.Infrastructure
          --startup-project src/ProductName.Api
          -r linux-x64 --self-contained
          -o artifacts/migrations/efbundle

      - uses: actions/upload-artifact@v4
        with:
          name: productname-${{ github.sha }}
          path: artifacts/
```

- 以 GitHub Actions 为例；使用其他 CI 平台时，按相同步骤改写。
- 每次推送与合并请求都会建置并执行全部测试（包括以 Testcontainers 执行的整合测试）；只有测试通过才产生部署产物。
- 产物包含 Api、Worker 与迁移程序，部署步骤见 [8.21](../spec/08-design-rules/21-deployment.mdx)。
- 未选择 Worker 的项目，删除发布 Worker 的步骤。
- 第一次 push 之前先设定 `MT_LICENSE` secret：整合测试会启动 MassTransit，没有授权就无法执行（`gh secret set MT_LICENSE < license.txt`）。

<Optional when="sonar,qodana">

**可选：代码品质检查（SonarCloud 与 Qodana）**

来自英文 guide。需要静态分析与覆盖率报告时，在 `ci.yml` 的 `jobs:` 下加入以下两个 job，它们在 `build` 通过后并行执行。整合测试以 Testcontainers 自行启动数据库，因此不需要 CI 的 `services`。

```yaml
  # @@sonar-begin
  sonar:
    name: SonarCloud
    runs-on: ubuntu-latest
    needs: build
    env:
      MT_LICENSE: ${{ secrets.MT_LICENSE }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-dotnet@v4
        with:
          global-json-file: global.json

      # SonarScanner 需要 Java
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "17"

      - run: dotnet tool install --global dotnet-sonarscanner

      - run: >
          dotnet sonarscanner begin
          /k:"${{ vars.SONAR_PROJECT_KEY }}"
          /o:"${{ vars.SONAR_ORGANIZATION_KEY }}"
          /d:sonar.token="${{ secrets.SONAR_TOKEN }}"
          /d:sonar.host.url="https://sonarcloud.io"
          /d:sonar.cs.vscoveragexml.reportsPaths="TestResults/*.xml"
          /d:sonar.exclusions="**/obj/**,**/bin/**"
          /d:sonar.coverage.exclusions="**/obj/**,**/bin/**,**/Migrations/**"

      - run: dotnet build -c Release

      - run: >
          dotnet test --no-build -c Release
          --coverage --coverage-output-format xml
          --results-directory TestResults

      - run: dotnet sonarscanner end /d:sonar.token="${{ secrets.SONAR_TOKEN }}"

  # @@sonar-end
  # @@qodana-begin
  qodana:
    name: Qodana
    runs-on: ubuntu-latest
    needs: build
    permissions:
      contents: write
      pull-requests: write
      checks: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: JetBrains/qodana-action@v2025.1
        env:
          QODANA_TOKEN: ${{ secrets.QODANA_TOKEN }}
  # @@qodana-end
```

## 12.11 AI Coding Agent 提示词 \{#12-11-ai-coding-agent-prompt\}

<Prompt12Solution />
