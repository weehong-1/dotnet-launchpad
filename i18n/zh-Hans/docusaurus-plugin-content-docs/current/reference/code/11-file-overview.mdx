## 11.1 使用 AI Coding Agent 生成 \{#11-1-generating-with-an-ai-coding-agent\}

每一节末尾都附有提示词，可交给 AI Coding Agent（例如 Claude Code、Cursor、GitHub Copilot）生成该节的文件。

**使用步骤**

1. 下载 `TEMPLATE.md`（整个 Reference 合成的单一文件，见 [Setup Flow 步骤 1.1](../../setup/repository.mdx)），放进新项目的存储库，路径为 `docs/TEMPLATE.md`，让 AI 可以读取。
2. 把下方的**共通规则**填好项目设定后，放进 AI 的项目指示档（例如 `CLAUDE.md`、`AGENTS.md`，或 GitHub Copilot 自动读取的 `.github/copilot-instructions.md`）；工具不支持项目指示档时，就在每次对话开头贴上。
3. 按第 [12](./12-solution-level.mdx) 至 [18](./18-tests.mdx) 节的顺序，每次贴一节的提示词，确认完成条件都通过后，再进行下一节。
4. 想一次完成时，改用下方的**一次生成全部**提示词。建议第一次使用模板时逐节执行，比较容易发现问题。

项目指示档除了共通规则，建议另写明：建置与执行指令（见 [8.10](../spec/08-design-rules/10-local-development.mdx)、[8.11](../spec/08-design-rules/11-database-migrations.mdx)）、分层规则（见第 [3](../spec/03-layers-and-dependency-direction.mdx) 节）、主要约定（CQRS、Result、功能切片）、测试约定、技术栈与版本。

## 11.2 以 CLI 建立解决方案骨架 \{#11-2-scaffolding-the-solution-with-the-cli\}

不交给 AI 时，可用以下指令手动建立第 [5](../spec/05-solution-structure.mdx) 节的结构与 [12.2](./12-solution-level.mdx#12-2-directory-packages-props) 的项目引用，效果等同 [12.11](./12-solution-level.mdx#12-11-ai-coding-agent-prompt) 提示词的第 1、2、6 步。改写自英文 guide 的第 2、3 节，已换成本模板的项目名称与 xUnit v3。先安装 .NET 10 SDK 与 Docker。

<SnippetCliScaffold />

- 不需要 Worker 时，略过所有标有 Worker 的指令。
- 指令建立空项目与引用，把所有测试项目改为 net10.0，删除模板加入的包引用与范例，并把 Worker 模板的 `Program.cs` 换成不再注册已删除 `Worker` 类别的最小版本。之后按 [12.1](./12-solution-level.mdx#12-1-directory-build-props) 至 [12.10](./12-solution-level.mdx#12-10-github-workflows-ci-yml) 加入根目录文件，按 [12.2](./12-solution-level.mdx#12-2-directory-packages-props) 表格以不带版本的 `<PackageReference Include="..." />` 加入 NuGet 包。
- Windows PowerShell 改用 `$env:PROJECT = "ProductName"` 设定变量，其余指令相同（循环改用 `Get-ChildItem src/*/*.csproj | ForEach-Object { ... }`）。

## 11.3 各项目的 GlobalUsings.cs \{#11-3-globalusings-cs-per-project\}

Boilerplate 文件省略了解决方案内部命名空间的 `using`，改由每个项目根目录的一个 `GlobalUsings.cs` 统一提供，因此每个文件照抄即可编译。请在该项目的其他文件都建立**之后**再建立它：全局引用一个还不存在的命名空间会让编译失败。标示审计的行在不使用审计时省略。
