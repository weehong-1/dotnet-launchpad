# 1.3 加入 solution 级别文件

这些文件位于 repo 根目录，适用于每个项目：

- 共享的构建设定，把警告视为错误
- 一份集中的 NuGet 版本清单
- SDK 版本
- 代码风格
- 一个运行本地日志服务器 Seq 的 `docker-compose.yml`

[Reference 12](../reference/code/12-solution-level.mdx) 逐一说明它们。

<Tabs groupId="route" queryString>
<TabItem value="manual" label="手动" default>

**1. 在 repo 根目录创建这些文件。** 将 `global.json` 设为步骤 0.3 中的 SDK 版本。

<LayerFiles project="Solution" />

**2. 填入 package 版本。** `Directory.Packages.props` 中的每个 `Version=""` 都要填入 nuget.org 上最新的稳定版本；ASP.NET Core、`Microsoft.Extensions` 和 EF Core 的 package 与 SDK 一样保持在 10.x。下面的循环会完成这件事，做法与 scaffold 脚本相同：

<SnippetPackageVersions />

**3. 引用每个项目需要的 package**，按照 [12.2 表格](../reference/code/12-solution-level.mdx#12-2-directory-packages-props)。使用集中式 package 管理时，这些命令不会在 `.csproj` 中加入版本：

<FlagScope core>
<PackageCommands />
</FlagScope>

**4. 检查：**

```bash
dotnet build
docker compose config --quiet && echo "compose ok"
```
