# D.1 加入审计

<AddOnSwitch addon="auditing" />
<StepApplies step="auditing" />

审计从第一天起记录改了什么、谁做了什么（[Reference 7.3](../reference/spec/07-optional-components.mdx#7-3-audit-records)）。从未记录的历史之后无法恢复。它需要 PostgreSQL。

- **数据变更审计**：EF Core interceptor 为每个标记了 `IAuditable` 的实体的每次变更写入一行 `AuditTrails`，包含旧值和新值。
- **操作审计**：pipeline behavior 为每个标记了 `IAuditableRequest` 的 Command 或 Query 的每次执行写入一行 `OperationAudits`，失败的执行也包括在内。

在 SIT 和 Production（上线）上，应用程序账号不能修改或删除审计记录。

<Tabs groupId="route" queryString>
<TabItem value="manual" label="手动" default>

**1. 创建新文件，并把高亮的行加入**现有文件：

<AddOnFiles addon="auditing" />

```bash
dotnet build
```

**2. 为审计表创建 migration：**

<SnippetAddMigration />

migration 名称使用 `AddAuditTables`。打开它：它只能包含 `AuditTrails` 和 `OperationAudits` 表。

**3. 测试：**

```bash
dotnet test
```

**4. 在功能出现之前写下审计规则**：哪些类型的实体实现 `IAuditable`、哪些属性加上 `[AuditIgnore]`、哪些类型的 Command 或 Query 实现 `IAuditableRequest`。把规则写进 agent 指令文件，让每个 feature slice 都遵守。
