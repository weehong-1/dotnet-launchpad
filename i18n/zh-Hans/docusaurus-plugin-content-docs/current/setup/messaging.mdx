# B.2 加入消息

<AddOnSwitch addon="messaging" />
<StepApplies step="messaging" />

这个附加组件让系统通过 RabbitMQ 和 MassTransit，告诉外部世界或自己的 Worker 发生了某件事（[Reference 7.5](../reference/spec/07-optional-components.mdx#7-5-messaging)、[8.4](../reference/spec/08-design-rules/04-masstransit-async-messaging.mdx)）。它需要 PostgreSQL。

- Application 通过 `IEventBus` 发布**集成事件**，从不引用 MassTransit。
- MassTransit 的 **Outbox** 把每个事件与业务数据在同一个事务中写入一张表，然后再投递到 RabbitMQ。事件不会丢失，也不会为已回滚的数据发送。
- 每个 Consumer 都有 **Inbox**，所以被投递两次的消息只会处理一次。
- 没有 Worker 附加组件时，由 Api 自己投递 Outbox。

**1. 创建新文件，并把高亮的行加入**现有文件：

<AddOnFiles addon="messaging" />

**2. 填入新 package 的版本并引用这些 package：**

<SnippetPackageVersions />

<FlagScope addon="messaging">
<PackageCommands addon="messaging" />
</FlagScope>

```bash
dotnet build
```

**3. 为 Outbox 和 Inbox 表创建 migration：**

<SnippetAddMigration />

migration 名称使用 `AddMessaging`。打开它：它只能包含 MassTransit 的 `InboxState`、`OutboxMessage` 和 `OutboxState` 表。

**4. 运行。** 与其他本地服务一起启动 RabbitMQ，然后启动 Api：

```bash
docker compose up -d
echo $MT_LICENSE_PATH        # 步骤 B.1 的授权
dotnet run --project src/ProductName.Api
```

RabbitMQ 管理界面位于 [http://localhost:15672](http://localhost:15672)（guest / guest）。Seq 中的 Api 日志显示 bus 启动且没有错误。

**5. 测试**（Docker 必须在运行，并已设定 `MT_LICENSE_PATH`）：

```bash
dotnet test
```
