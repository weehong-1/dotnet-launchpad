# 3.2 运行 Api 和 Worker

各自在单独的终端中启动：

```bash
dotnet run --project src/ProductName.Api
dotnet run --project src/ProductName.Worker  # @@worker
```

在 Development 中，Api 会在启动时应用 migration。从 `Properties/launchSettings.json` 中取得 Api 的 URL，然后检查：

```bash
API=http://localhost:5000   # 使用 launchSettings.json 中的 URL
curl -i $API/health         # 200 且 Healthy，无需 token
curl -i $API/openapi/v1.json
curl -i $API/anything      # 401：默认所有 endpoint 都要求登录
```

在浏览器中打开 `$API/scalar` 查看 API 文档。

接着证明真实的 token 会被接受，而不只是缺少 token 会被拒绝。按步骤 0.5 的方法取得 Api audience 的 access token，然后：

```bash
TOKEN=<access token>
curl -i -H "Authorization: Bearer $TOKEN" $API/anything   # 404：已通过验证，只是路径不存在
```

如果这里返回 401，表示 `Authentication:Authority` 或 `Authentication:Audience` 与 token 不符，请先修正再继续。


然后证明在 Development 之外，没有真实设定时 Api 会拒绝启动：

```bash
ASPNETCORE_ENVIRONMENT=SIT dotnet run --project src/ProductName.Api --no-launch-profile
# 预期：启动时失败，而不是连接到本地数据库
```

最后，打开 [http://localhost:5341](http://localhost:5341) 上的 Seq，检查日志条目是否已到达。
